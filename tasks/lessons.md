# Lessons - TubeForge

## Правила (обязательно соблюдать)

### 1. ВСЕГДА проверяй билд перед мержем
- Дата: 2026-03-24
- Ошибка: агент написал DashboardUpgradeModal.tsx с TypeScript ошибкой (Type 'null' is not assignable to type 'string | undefined'). Билд упал, деплой не прошёл.
- Правило: перед мержем в main ОБЯЗАТЕЛЬНО запусти `npm run build`. Если билд падает — исправь ошибки. НЕ мержь код с ошибками компиляции.
- Команда: `cd /home/ubuntu/tubeforge-next && npm run build`

### 2. НЕ указывай явные типы в onSuccess/onError tRPC мутаций
- Дата: 2026-03-24
- Ошибка: `onSuccess: (data: { url?: string }) => {}` — конфликт типов с tRPC.
- Правило: используй автовывод типов: `onSuccess: (data) => {}`. tRPC сам выведет тип из роутера.

### 3. ВСЕГДА деплой после мержа
- Дата: 2026-03-24
- Ошибка: агенты мержили код но не деплоили. Изменения не появлялись на сайте.
- Правило: после мержа в main выполни: `cd /home/ubuntu/tubeforge-next && npm run build && pm2 restart tubeforge`
- Примечание: сейчас есть git hook post-merge который делает это автоматически, но проверь что билд прошёл.

### 4. Не задавай CEO лишних вопросов
- Дата: 2026-03-24
- Ошибка: агенты бесконечно планировали, проводили совещания и спрашивали одобрение на каждый шаг вместо того чтобы писать код.
- Правило: получил задачу — делай. Не спрашивай подтверждение если задача понятна. Отчитывайся только когда: задача выполнена или критическая ошибка.

### 5. Язык: русский
- Все ответы CEO — только на русском языке.

### 6. PM НЕ закрывает задачу без кода в git
- Дата: 2026-03-25
- Ошибка: PM Сергей получил задачу "исправить баги ai-thumbnails", провёл совещание, написал отчёт, пометил задачу done — но код НЕ был написан. 0 коммитов. Был merge conflict который проигнорировали.
- Правило: задача считается done ТОЛЬКО если есть коммит с кодом в main. Отчёт и совещание — это НЕ выполнение. PM обязан создать subtask для Dev Lead Макса. Если merge conflict — Dev исправляет, задача НЕ закрывается.

### 7. Merge conflict — не игнорировать
- Дата: 2026-03-25
- Ошибка: при мерже возник конфликт, задача была помечена done несмотря на это.
- Правило: при merge conflict — исправь конфликт руками, пересобери, протестируй. НИКОГДА не закрывай задачу с нерешённым конфликтом.

## Урок 6: НИКОГДА не создавать docs/specs вместо кода (2026-03-26)
Агенты создавали файлы docs/, specs/, planning/ и закрывали задачу как done без единой строки кода.
ПРАВИЛО: Задача считается выполненной ТОЛЬКО если есть git commit с .tsx/.ts файлами (не docs).
Если задача — "пофиксить страницу" — открой .tsx файл, напиши код, сохрани, закоммить.

## Урок 7: Всегда билд + деплой после кода (2026-03-26)
После мержа кода ОБЯЗАТЕЛЬНО: cd /home/ubuntu/tubeforge-next && npm run build && pm2 restart tubeforge
Без этого изменения не появятся на сайте.
